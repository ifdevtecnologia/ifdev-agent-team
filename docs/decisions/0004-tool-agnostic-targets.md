## Context

The owner wants the toolkit to be tool-agnostic, with Claude Code, OpenAI Codex and Cursor as equal first-class targets: Codex now, Cursor next. Today every installed source lives in `claude/` in Claude Code's formats (agent `tools`/`disallowedTools`, `$ARGUMENTS`, `disable-model-invocation`), and the text holds 54 home-relative Claude paths (40 to rules, 11 to skills, 2 to the global `CLAUDE.md`, 1 to `settings.json`) plus Claude-only names in prose (project paths such as `.claude/rules/`, `$ARGUMENTS`, `argument-hint`). 0003 rejected a neutral source because moving managed paths breaks installed machines. This record keeps the AGENTS.md compatibility rules (moved sources are handled explicitly, validator and tests updated, Upgrade notes, safe and idempotent installs, temporary HOME in tests) and makes the move safe instead of avoiding it.

## Codex PoC (2026-11-02) [V]

`env -i PATH=$PATH HOME=$T CODEX_HOME=$T/.codex codex debug prompt-input` (no login, no model call), `$T` from `mktemp -d`, a project with its own `AGENTS.md`:

- A 36,051-byte global `~/.codex/AGENTS.md` (an adapter note + `claude/CLAUDE.md` + 3 rules), linked as a symlink, rendered whole (start and end markers present), followed by the project `AGENTS.md`. With `-c project_doc_max_bytes=1000` it still rendered whole: in 0.160.0 the 32 KiB cap does not apply to the global file.
- Skill directories symlinked into `~/.agents/skills/` were listed; `work-session` with `agents/openai.yaml` (`policy.allow_implicit_invocation: false`) was **not** listed for implicit use.
- Codex's own prompt says it spawns sub-agents only when the user, `AGENTS.md` or a skill asks, and documents `fork_turns` (`"none"` for a clean context).
- A custom agent TOML in `~/.codex/agents/` (symlinked) does not appear in the rendered input, and a malformed one raised no error: registration stays **unverified** (needs a session).

## Options considered

| | A. Keep `claude/`, neutralize text only | **B. Neutral `core/` + per-tool `targets/` + committed `dist/`** | C. Neutral `core/`, git-ignored build at install time (0003's B) |
|---|---|---|---|
| Neutral layout and formats | no: Claude formats remain the source | yes | yes |
| Update by `git pull` alone | yes | yes (generated files are tracked) | no: agents and Codex/Cursor files go stale until the installer reruns |
| Installer | links only | links only | gains a build step that writes into the checkout |
| Review | one copy | sources plus generated diffs (marked generated) | sources only |
| Compatibility cost | none | moved sources, bridged by compat links and a moved-item rule | same as B |
| Plugin (0002) | root `claude/` | root can be a committed `dist/claude/` | impossible without a build |

A per-tool plugin set (0003's C) stays rejected: no Codex global instructions and Cursor plugins need copies.

## Decision (proposed)

Adopt **B**. Sources become tool-neutral; every tool-specific file is either a small hand-written adapter in `targets/<tool>/` or generated into `dist/<tool>/`, committed and checked fresh by the validator.

### 1. Layout

```text
core/                         edit here; no tool-specific paths or wording
  instructions.md             team process (was claude/CLAUDE.md)
  rules/*.md                  engineering-principles, testing, git-workflow
  agents/<role>.md            frontmatter: name, description, read_only (bool); body
  skills/<name>/              Agent Skills SKILL.md (+ references/; work-session also agents/openai.yaml)
targets/<tool>/               hand-written: adapter.md, agent-footer.md; claude/hooks/, codex/notify/
dist/<tool>/                  generated by scripts/build_targets.py, committed, never edited
scripts/agent-notify.sh       shared notifier (unchanged path)
```

- **Agents:** `read_only` replaces tool lists (every role uses read, search and shell; writers add file edits). Claude: `tools: Read, Glob, Grep, Bash` (+ `Write, Edit`) and `disallowedTools: Write, Edit` when read-only, exactly today's frontmatter. Cursor: `name`, `description`, `readonly: true` when read-only. Codex: TOML `name`, `description`, `developer_instructions` (body + footer), with a generated-file comment; read-only is by instruction only [D].
- **Skills** stay in place in the open standard and are linked, not generated. Tool keys are a tolerated superset: `disable-model-invocation` (Claude, Cursor [D]) must be paired with `agents/openai.yaml` (Codex [V]); `argument-hint` is a Claude UI hint, ignored elsewhere [A].
- **Global instructions per tool (generated):** Claude `dist/claude/CLAUDE.md` = adapter + instructions (rules stay separate links, auto-loaded); Codex `dist/codex/AGENTS.md` = adapter + instructions + rules (about 37 KB); Cursor `dist/cursor/user-rules.md` = a first line with a content hash + adapter + instructions + rules.
- **Generator:** `scripts/build_targets.py`, standard library, Python 3.9+: sorted inputs, LF, no timestamps or absolute paths, idempotent writes; `--check` exits non-zero on any stale or extra file in `dist/`. TOML strings are escaped by a tested function (parsed back with `tomllib` in tests when available). `.gitattributes` marks `dist/**` as generated.

### 2. Neutral text and cross-references

- `core/` refers by **name**: "the `testing` rule", "the `web-dev` skill", "the global instructions", "the `reviewer` role". The three rules are always in the main agent's context in every target (Claude rules dir, inside Codex `AGENTS.md`, inside the Cursor paste), so names need no path.
- Each target appends `targets/<tool>/agent-footer.md` (2–3 lines) to every generated agent, saying where a role finds named rules and skills in that tool: Claude `~/.claude/rules/<name>.md` and skills by name; Codex and Cursor: the rules are in the global instructions, skills by name.
- `instructions.md` defines once "project instructions": `AGENTS.md` plus the tool's project files (for example `CLAUDE.md` and `.claude/`, `.codex/`, `.cursor/rules/`); agents and skills say "the project's instructions". `$ARGUMENTS` becomes "the request that invoked this skill"; "subagent", "Agent tool" and "Skill tool" become "start the role in a fresh context" and "use the skill".
- **Adapter notes** (`targets/<tool>/adapter.md`, under 1 KB each, first in each generated global file): Claude: roles are subagents of the same name, read-only enforced. Codex: start a role with `spawn_agent` using the custom agent of the same name and `fork_turns: "none"`, passing objective, criteria and scope; a full-history fork is not an independent review; read-only roles are read-only by instruction, and any edit by one is reported. Cursor: delegate to the subagent of the same name (read-only roles have `readonly: true`). The fallback for a tool without fresh contexts (say "independent review not performed", report PARTIAL, or a new session per role with a written hand-off) is neutral and lives in `instructions.md`.
- Validator: no `~/.claude/`, `~/.codex/` or `~/.cursor/` paths, `$ARGUMENTS` or "Skill tool"/"Agent tool" in `core/`; global references are resolved through the item table's destinations instead of the fixed `claude/` prefix.

### 3. Targets, items and state

- `MANAGED_ITEMS` gains a third field, the owning targets: `"<source>|<destination>|claude,codex"`. A destination listed for several targets is a **shared item**; ownership is derived from the item table plus the installed-target list, so no per-item records are needed.
- `install.sh --target claude|codex|cursor|all` (repeatable) and `uninstall.sh --target ...`. Bare `install.sh` reinstalls the targets recorded in `~/.ifdev-ai-tools/targets` (one name per line, written atomically under the existing lock). With no state file, a machine with any exact link to this checkout (old or new source) is a legacy install and records `claude`, so today's `./scripts/install.sh` keeps working. A fresh machine without `--target`: see blocking question 1. Bare `uninstall.sh` removes all recorded targets (today's behavior).
- Uninstalling a target removes its items except shared ones still owned by another recorded target; the Claude settings hooks are touched only for `claude`. Everything else is unchanged: plan before mutating, exact-link removal, backups, dry run, symlinked parents refused (now also `~/.agents`, `~/.cursor`, `~/.codex/agents`), idempotent reruns.
- **Moved sources:** new `MOVED_ITEMS` (`"<old source>|<destination>"`): an exact link to the old source is relinked without a backup and removed by uninstall. For one release, tracked compat links keep old links resolving after a plain `git pull`: `claude/CLAUDE.md`, `claude/rules`, `claude/skills`, `claude/agents`, `claude/hooks` and `codex/notify` point into `dist/claude`, `core` and `targets` (read-only enforcement survives, because `claude/agents` points at generated Claude agents). The validator accepts only listed compat links inside the repository; a later release moves them to `RETIRED_ITEMS` with an Upgrade note.

| Target | Global instructions | Agents | Skills | Notifications |
|---|---|---|---|---|
| claude | `~/.claude/CLAUDE.md` → `dist/claude/CLAUDE.md`; rules `~/.claude/rules/` → `core/rules/` | `~/.claude/agents/` → `dist/claude/agents/` | `~/.claude/skills/` → `core/skills/` | as today: hook script, notifier, `~/.claude/settings.json` merge |
| codex | `~/.codex/AGENTS.md` → `dist/codex/AGENTS.md`; an existing file is backed up; the installer warns when `AGENTS.override.md` exists | `~/.codex/agents/<role>.toml` | `~/.agents/skills/<name>`, shared with cursor | `~/.codex/notify/` adapter + notifier; `config.toml` never edited |
| cursor | no file location exists [D]: `dist/cursor/user-rules.md` to paste into User Rules; the installer stores its hash in the state dir and prints a re-paste reminder when it changes | `~/.cursor/agents/<role>.md`, which win over the Claude dir on name clashes [D] | `~/.agents/skills/<name>`, shared with codex | deferred: only `Stop` maps [D] |

- The Codex notify adapter is installed by both `claude` (legacy, until a later release) and `codex`; it calls `~/.codex/notify/agent-notify.sh` and falls back to `~/.claude/hooks/agent-notify.sh`.
- Cursor alternatives rejected for now: a local plugin copy (`~/.cursor/plugins/local` skips outside symlinks [D], so it needs copies and a new copy-ownership mechanism that breaks the links-only contract, and it is off by default on Enterprise [D]); project-level rules (would copy global defaults into every project).

## Consequences and risks

- **Generated duplication and noisy diffs.** Mitigation: generated marking, `--check` in the validator and CI, `dist/` never hand-edited.
- **Upgrade window.** Compat links and `MOVED_ITEMS` keep old installs working; signal: dangling links in `install.sh --dry-run`.
- **Weaker Codex independence** (fork by default, read-only unenforced). Mitigation: adapter text, reporting rule; revisit if Codex adds per-agent sandboxing.
- **Codex global size** (~37 KB) works in 0.160.0 [V]; a later cap would truncate the rules. Signal: an optional `codex debug prompt-input` test (skipped and reported when `codex` is missing) checks for an end marker.
- **Cursor:** drift of the pasted rules (hash reminder); duplicate skills from `~/.claude/skills/` and `~/.agents/skills/` when several targets are installed (precedence undocumented); not installed here, so all Cursor behavior is [D] or [A] until the manual checklist runs.
- **Churn** in all three tools: recheck docs and versions at each release.
- **Revisit when** Cursor gets file-based user rules, Codex enforces read-only custom agents, a tool reads a shared rules location, or a fourth target is requested.

## Implementation slicing

Every slice runs `bash -n` on the scripts, `scripts/validate.sh`, the unittest suite, adds CHANGELOG entries and leaves existing installs working.

1. **A. Foundation (dev).** Move to `core/`, `targets/`, `dist/`; neutral agent frontmatter; generator with `--check`; item table with targets, `MOVED_ITEMS`, compat links, state file, `--target` (only `claude` enabled); validator (freshness, frontmatter schema, read-only on `core` and `dist`, compat links, reference mapping). Acceptance: the Claude target installs the same 33 destinations, and the generated Claude files are byte-identical to today's sources (golden test); a simulated pre-0004 install relinks without backups; bare install and uninstall behave as today; dry run and rerun idempotent.
2. **B. Neutral text (dev, tech-writer).** By-name references, project-instructions definition, `$ARGUMENTS` removal, Claude adapter and footer, notifier fallback; validator bans tool paths in `core/`. Acceptance: no tool-home paths in `core/`; Claude output differs only by adapter, footer and wording; context budget updated.
3. **C. Codex target (dev).** Codex `AGENTS.md`, TOML agents, shared skills, `openai.yaml`, notify items, override warning, existing-file backup. Acceptance: temporary-HOME tests for install, uninstall and claude+codex co-install (uninstall of one keeps the other's items); optional prompt-input test; manual session check that custom agents are offered to `spawn_agent`.
4. **E. Docs and release (tech-writer, dev).** README, customization guide, templates, CHANGELOG 0.2.0 cut. Acceptance: validator links pass; Upgrade note covers the move.
5. **D. Cursor target (dev).** Cursor agents, paste file with hash reminder, shared skills, docs. Acceptance: temporary-HOME tests including codex+cursor shared skills ownership; a manual checklist on a Cursor machine (agents and `readonly`, which agent and skill win, symlinks followed, paste size accepted) before "preview" is lifted.
6. **Follow-ups.** Codex `Stop` hooks; Cursor `stop` hook; 0002 plugin on `dist/claude`.

## Owner decisions (2026-11-02)

The owner accepted the recommended defaults:

1. Bare `install.sh` on a fresh machine fails with "choose `--target`" and changes nothing; existing installs are detected as `claude`.
2. Generated output is committed in `dist/` and checked fresh by the validator.
3. Compatibility links at the old paths are kept for one release.
4. Cursor global instructions would use the paste file with a hash reminder.
5. Release 0.2.0 after slices A, B, C and E; tagging needs the owner's authorization.
6. The Codex target backs up and replaces an existing `~/.codex/AGENTS.md`.
7. The owner updates the repository description.

**Cursor is deferred:** slice D is not implemented for now. The layout keeps room for `targets/cursor/`, but `--target cursor` is not offered and Cursor is not listed as supported until the owner resumes it.
